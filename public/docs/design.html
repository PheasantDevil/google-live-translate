google-live-translate

v0.1 設計フェーズ 作成日: 2026-08-20  |  リポジトリ: PheasantDevil/google-live-translate

概要

本プロジェクトは、Google 翻訳アプリの Live translate（リアルタイム翻訳） 機能に相当する Web アプリケーションを構築する。ユーザーがマイクで話した内容を、数秒以内の遅延で 指定言語の自然な音声に翻訳して再生する。

スコープ: Live translate のコア体験（音声入力 → リアルタイム翻訳音声出力）に限定する。 テキスト翻訳、カメラ翻訳、会話モードの双方向 UI、オフライン辞書等は 含めない。

1. 要件定義

1.1 機能要件（Must Have）

ID 機能 説明
F-01 マイク入力 ブラウザの getUserMedia でマイク音声を取得。権限リクエスト UI を表示。
F-02 リアルタイム翻訳 入力音声を Gemini Live API（gemini-3.5-live-translate-preview）へストリーミングし、翻訳音声を連続再生。
F-03 翻訳先言語選択 ユーザーが翻訳先言語（BCP-47）を選択。入力言語はモデルが自動検出（70+ 言語）。
F-04 開始 / 停止 セッションの開始・一時停止・終了。状態を UI に明示表示。
F-05 音声出力 翻訳音声をスピーカーまたは接続ヘッドフォンで再生（Google Translate の Listening モード相当）。
F-06 字幕表示（オプション） 翻訳テキストを画面下部にリアルタイム表示（Google Translate の Text only 相当の簡易版）。

1.2 機能要件（Should Have — Phase 2）

  • 出力先切替: スピーカー / ヘッドフォン（setSinkId 対応ブラウザ）
  • 音量メーター（入力レベル可視化）
  • セッション再接続（15 分タイムアウト対策）
  • PWA 対応（ホーム画面追加、バックグラウンド継続の検討）

1.3 非機能要件

項目 目標
レイテンシ 話者から 2〜5 秒以内に翻訳音声が開始（Gemini 3.5 Live Translate の仕様に準拠）
対応ブラウザ Chrome / Edge 最新、Safari 17+（WebSocket + AudioWorklet 対応）
モバイル iOS Safari / Android Chrome で動作（HTTPS 必須）
可用性 セッション切断時にユーザーへ通知し、手動または自動再接続
セキュリティ API キーをクライアントに露出しない（Ephemeral Token パターン）

2. 技術調査

2.1 Google 翻訳 Live translate の技術基盤

Google 翻訳アプリの Live translate は Gemini 3.5 Live Translate モデルを使用。 従来の ASR → 機械翻訳 → TTS パイプラインではなく、 音声入力 → 音声出力の End-to-End ストリーミング により低遅延を実現している。

  • 70+ 言語の自動検出
  • 話者のイントネーション・ペーシングを保持した自然な翻訳音声
  • ターン待ちではなく連続ストリーミング（同時通訳型）
  • ノイズ耐性（騒がしい環境でも動作）

2.2 開発者向け API 選定

方式 概要 評価
Gemini Live API
gemini-3.5-live-translate-preview 		WebSocket による音声ストリーミング。translationConfig で翻訳先言語を指定。Google Translate と同一技術。 採用
Cloud STT + Translation + TTS 3 段パイプライン。レイテンシ大、プロソディ再現が困難。 不採用
Web Speech API + Cloud Translation テキストベース。音声→音声の Live translate 体験と乖離。 不採用
Google Translate Widget / 非公式 API Live translate 非対応。利用規約リスク。 不採用

2.3 Gemini Live API — 音声フォーマット仕様

方向 フォーマット 備考
入力 Raw 16-bit PCM, 16 kHz, mono, little-endian 100ms チャンク推奨
出力 Raw 16-bit PCM, 24 kHz, mono, little-endian Web Audio API で再生
入力種別 音声のみ 翻訳モードではテキスト入力非対応

2.4 translationConfig

{
  "generationConfig": {
    "translationConfig": {
      "targetLanguageCode": "ja",
      "echoTargetLanguage": false
    }
  }
}
  • targetLanguageCode: 翻訳先言語（BCP-47）。例: ja, en, es
  • echoTargetLanguage: true なら入力が既に翻訳先言語の場合エコー。Live translate では通常 false。

5. データ設計・状態管理

5.1 状態管理方針

React Context + useReducer による軽量状態管理。 外部ストア（Redux 等）は不要。音声処理は Ref ベースの imperative モジュールと連携。

5.2 主要 State 型

type SessionStatus =
  | "idle"           // 未開始
  | "requesting_mic" // マイク権限要求中
  | "connecting"     // WebSocket 接続中
  | "translating"    // 翻訳中
  | "paused"         // 一時停止
  | "reconnecting"   // セッション再接続中
  | "error";         // エラー

interface TranslateState {
  status: SessionStatus;
  targetLanguage: string;       // BCP-47, e.g. "ja"
  subtitles: SubtitleLine[];
  audioLevel: number;           // 0–1
  error: AppError | null;
  sessionStartedAt: number | null;
}

interface SubtitleLine {
  id: string;
  text: string;
  timestamp: number;
  isFinal: boolean;
}

5.3 永続化

  • localStorage: 最後に選択した翻訳先言語のみ保存
  • 音声データ・翻訳履歴はサーバーに保存しない（プライバシー配慮）

5.4 サーバー側データ

ステートレス。DB 不要。Route Handler は Ephemeral Token 発行のみ。

6. API 設計

6.1 POST /api/live-token

クライアント向け Ephemeral Token を発行する。

項目 内容
Request Body { "targetLanguage": "ja" }
Response 200 { "token": "...", "expiresAt": "ISO8601" }
Response 400 無効な言語コード
Response 500 API キー未設定 / Google API エラー
Rate Limit IP あたり 10 req/min（Vercel Edge Middleware または Upstash Redis）

6.2 Gemini Live WebSocket フロー

  1. クライアントが /api/live-token からトークン取得
  2. wss://generativelanguage.googleapis.com/ws/.../BidiGenerateContent に接続（v1alpha）
  3. Setup メッセージ送信（model + translationConfig）
  4. 100ms ごとに PCM チャンクを realtimeInput.mediaChunks で送信
  5. サーバーから翻訳音声 PCM + テキスト transcript を受信
  6. GoAway 受信時 → 新トークン取得 → シームレス再接続

7. 音声パイプライン詳細

7.1 キャプチャフロー

getUserMedia({ audio: { echoCancellation: true, noiseSuppression: true } })
  → AudioContext (sampleRate: 48000)
  → AudioWorklet (resample to 16kHz)
  → Int16Array PCM buffer
  → Base64 encode → WebSocket send (every 100ms)

7.2 再生フロー

WebSocket receive (24kHz PCM base64)
  → decode → Float32Array
  → AudioBufferQueue (scheduled playback)
  → AudioContext.destination (speaker)

7.3 バッファリング戦略

  • 初期バッファ: 200ms 分蓄積後に再生開始（ジッター吸収）
  • 最大バッファ: 2 秒（遅延が増えすぎたら古いチャンクをドロップ）
  • Barge-in: ユーザーが話し始めたら再生キューをフラッシュ

8. セキュリティ

脅威 対策
API キー露出 Ephemeral Token パターン。キーは Vercel 環境変数のみ。
translationConfig 改ざん サーバー側トークン発行時に targetLanguage をロック
Token 乱用 Rate limiting、Token 有効期限（数分）、CORS 制限
マイク権限 HTTPS 必須（Vercel デフォルト）、Permissions-Policy ヘッダー
音声データ サーバー経由で保存しない。Google API 送信のみ。
注意: Gemini API の利用規約および SynthID 透かし（生成音声への AI 透かし）に準拠すること。 商用利用時は Google Cloud / AI Studio の料金体系を確認すること。

10. 懸念事項・エッジケース

10.1 技術的懸念

懸念 影響 対策
セッション 15 分制限 長時間利用で切断 GoAway メッセージ監視 → 30 秒前に新セッション確立 → クロスフェード再接続
ブラウザ AudioWorklet 非対応 古いブラウザで動作不可 対応ブラウザチェック + フォールバックメッセージ表示
iOS Safari バックグラウンド タブ非アクティブでマイク停止 Phase 1 では警告表示。Phase 2 で PWA + Wake Lock 検討
API コスト 従量課金 Rate limit、セッション時間上限（任意）、利用量モニタリング
v1alpha API 変更 破壊的変更リスク SDK バージョン固定、Preview モデル変更の監視
ネットワーク不安定 音声途切れ 指数バックオフ再接続、UI で状態通知

10.2 UX エッジケース

  • マイク権限拒否 → 設定手順ガイドを表示
  • 入力言語 = 翻訳先言語 → モデルは無音（echoTargetLanguage: false）
  • 無音状態が続く → 「話してください」プロンプト（5 秒後）
  • ヘッドフォン未接続 → スピーカー出力（周囲に聞こえる旨を通知）
  • 複数タブで同時起動 → 先勝ち、後からは「他タブで使用中」表示

10.3 パフォーマンス目標

指標 目標

セッション開始〜初翻訳音声 < 5s
